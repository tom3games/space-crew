# 宇宙船クルー

全員で1隻の宇宙船を動かし、危険な宙域を抜けて目的地のビーコンまで運ぶ協力ゲーム。担当ごとに操作盤が違い、危険地帯が見えるのはナビだけ。声を掛け合わないと着かない。スマホでリンクから参加する。

- 人数: おすすめ3〜8人（1〜2人でも遊べる。兼任になる）
- 1プレイ: 発進前の担当確認4秒＋航行（航路ごとに120〜260秒＋中継ラインのボーナス）
- 手元のポート: 8106

画面は 3D（Three.js）。船を後ろの少し上から追いかける視点で、カメラは船の向きについていく（「左へ」を押すといつも画面の左へ曲がる）。窓の中にクルー全員が乗っていて、こちらを振り向いて表情を変える。WebGL が使えない端末では、船を中心に進む向きを上にした 2D に自動で戻る（`?2d` を付けると 2D で確かめられる）。

## 遊び方

1. ホストが部屋を作り、招待URL（`/r/コード`）を送る。みんなはニックネームを入れて参加
2. ホストが航路（5つ）を左右の矢印で選ぶ。参加者の画面にも同じ航路が出る
3. 「発進準備」を押すと担当が配られ、4秒間その説明が出る
4. 船を目的地（緑のビーコン）まで運べば勝ち

| 担当 | 操作 | 見えるもの |
|---|---|---|
| 操縦 | 左へ・まっすぐ・右へ（切り替え式。1回押すと曲がりっぱなし、もう1回かまっすぐで戻る） | 前方の景色、近くの隕石、目的地の方向、ナビの目印。**危険地帯は見えない** |
| エンジン | 出力4段（停止・低速・巡航・全開）、冷却 | 速度、熱、電力 |
| 修理 | 壊れた装置をタップ連打 | 5つの装置の状態 |
| ナビ | 地図をタップして目印を置く | **航路全体の地図と、岩場・電磁嵐**（3D の景色にも出る） |
| 防衛 | 上の 3D 画面をタップした方向に撃つ。「近い隕石を撃つ」は先読みして撃つ | 遠くまでの隕石 |

全員が見えるもの: 船体・電力・酸素、進み具合と区間、残り時間、故障中の装置、重力井戸と補給ポッド、掛け声（クルーの頭の上に吹き出し）。
故障の札をタップすると「○○を修理して」と全員に出る。担当ごとの掛け声ボタン（左へ・減速して・隕石が来る など）と、全員の「手伝って・ナイス・ごめん」がある。

PC は 矢印キー（押している間だけ曲がる）/ 1〜4 で出力 / V か スペースで冷却 / 1〜5 で修理 / スペースで撃つ / Tab で担当の切り替え。

### 人数ごとの担当

| 人数 | 担当 |
|---|---|
| 1 | 1人で全部 |
| 2 | 操縦+エンジン / ナビ+修理+防衛 |
| 3 | 操縦+エンジン / ナビ+防衛 / 修理 |
| 4 | 操縦 / エンジン+修理 / ナビ / 防衛 |
| 5 | 1人1担当 |
| 6〜8 | 5担当＋修理と防衛を増やす（6: 修理2、7: 修理2・防衛2、8: 修理3・防衛2） |

並びは毎回混ぜるので、再戦すると担当が変わる。途中で抜けた人の担当は、担当の少ない人に引き継がれる。

## 航路（5つ）

どれも区間（3つ、ロングは5つ）に分かれていて、区間の境目の中継ラインを越えると残り時間が増え（+15〜30秒）、船体が15直る。そのかわり次の区間は隕石と故障が起きやすくなり（最初の0.75倍 → 最後の1.4倍）、出来事が起き始める。危険地帯も奥ほど多く大きい。

| 航路 | 長さ / 制限 | 中身 |
|---|---|---|
| 月までおつかい | 4200 / 120秒 | 練習用。岩場3・電磁嵐1。出来事は最後の区間で流星群だけ |
| 小惑星帯 | 6000 / 150秒 | 岩場8。流星群と宇宙ネコ |
| 電磁嵐の海 | 6000 / 150秒 | 電磁嵐8で故障が止まらない。宇宙ネコと太陽風 |
| ブラックホールの縁 | 6600 / 165秒 | 重力井戸3（吸い込まれ、芯で船体が削れる）。太陽風と流星群 |
| 銀河横断（ロング） | 15000 / 260秒 | 全部入りで5区間。中継ライン1つで+30秒 |

出来事:
- 流星群: 3秒前に予告。8秒間、隕石が4倍来る
- 太陽風: 3秒前に「左から/右から」と予告。7秒間、船が横に流される
- 宇宙ネコ: だれかの操作盤に乗る。乗られた人は連打（6回）で追い払うまで操作できない。ほうっておくと10秒で去る

補給ポッド（全員に見える）: 修理キット（船体+25）・酸素ボンベ（酸素+40）・電池（電力+50、熱-40）。

## ルール

- **勝ち**: 目的地から半径200以内に入る。星は船体40以上で2つ、船体75以上かつ残り時間が2割以上で3つ
- **負け**: 船体0（大破）／酸素0／時間切れ
- **故障**（操舵装置・エンジン・センサー・砲台・生命維持）: 勝手に起きる（人数が多いほど・区間が進むほど起きやすい）。隕石が当たったとき、電磁嵐の中、エンジンの過熱でも起きる。修理のタップ12回で直る
  - 操舵装置: 舵が効かず勝手に少しずつ曲がる / エンジン: 速度が20まで落ちる / センサー: ナビの地図が消え目印も置けない / 砲台: 撃てない / 生命維持: 酸素が毎秒3.5減る
- **岩場**: 中にいる間、船体が削れる（速いほど多く）。**電磁嵐**: 電力が減り、故障しやすい。**航路の外**: 船体が削れる
- **電力**: 毎秒4回復。出力が高いほど使う。1発6、冷却12。0になると低速までしか出ない
- **熱**: 全開で毎秒9たまり、100でエンジン故障。巡航ではゆっくりたまり、低速・停止で冷える
- 全部は直せない。何から直すか、どこを通るかを決めるのがこのゲームの判断

## 演出と記録

- 発進・中継ライン・流星群の予告・宇宙ネコ・到着・大破などで、画面の真ん中に帯が出て音が鳴る
- クルーの表情: ふつう（まばたき）／叫ぶ（掛け声）／驚き（被弾）／焦り（自分の担当の装置が故障・船体が少ない）／めまい（電磁嵐・重力井戸）／青い顔（酸素が少ない）／むっ（ネコに乗られた）／笑顔（補給・修理・到着）
- 終わり方ごとの余韻（2.4秒）: 到着＝カメラが船のまわりを回って紙吹雪とクルーが跳ねる／大破＝船がばらばらになり、クルーが窓から飛び出してくるくる回る／酸素切れ＝全員青い顔／時間切れ＝泣き顔
- 結果画面: ハンコ（到着・船が大破…）と一言（「保険はききません」など）、星、成績6つ、通った航路の地図、クルーごとの称号（修理の鬼・撃ち落とし名人・謝罪王・乗ってただけ など）
- チームの称号12種（伝説のクルー・無傷の航海・ギリギリ生還・あと一歩で爆発 など）。初めて取ったものに NEW。集めた数と航路ごとの自己ベスト（星と秒）はこの端末に残り、ロビーの航路の欄にも出る
- BGM は航路ごとに音の並びと速さを変える（Web Audio。右上で消せる）

## 起動

```
npm install
npm start
```

ブラウザで http://localhost:8106 を開く。別のポートは `PORT=8080 npm start`。

## テスト

```
npm test                       # ルールの単体テスト・ルーム管理・WebSocket の統合テスト（56件）
npx playwright install chromium webkit   # 初回だけ
node tools/e2e.mjs             # 実ブラウザ（chromium と webkit）で3人プレイを最後まで通す
node tools/sim.mjs [航路] [回数] # 自動操縦（全部見えている上手なクルー）で全航路を回し、着く割合・秒数・船体を表にする
node tools/shot-scenes.mjs     # 出来事・終わり方・航路ごとの 3D 画面を、通しで遊ばずに撮る
node tools/fps.mjs             # GPU を使う headless Chromium で、スマホ相当（390x844・画素比3）と横持ちの fps を全航路ぶん測る
node tools/make-og.mjs         # og.png を作り直す（実際の 3D 画面にロゴを重ねる）
node tools/live-check.mjs <URL> # 公開URLで2人（chromium と webkit）つなぎ、最後まで飛んで再戦・起動エラーの誤表示なし・OGP を確かめる
```

`tools/e2e.mjs` は、作成→招待URLで参加→航路の選択（参加者にも見える）→担当の確認→5担当が3人に分かれる→地図はナビにだけ届く→3D が描けている（画素の分散）・`?2d` の人は 2D で描けている→舵の切り替え→掛け声が他の人に吹き出しで届く→各担当の操作盤だけを触って目的地まで運ぶ（防衛は 3D 画面のタップでも撃つ）→結果→再戦 を通す。390x844 / 360x640 / 844x390 / 568x320 で全画面・全担当の操作盤が上下にスクロールせず収まり、ボタンが44px以上あるかも数値で確かめる。コースは短く（距離1800）してある。スクショは `tools/shots/`。

## 仕組み

- 状態はサーバー（`lib/game.mjs`）だけが持つ。物理は内部で1/30秒の固定ステップ、送信は毎秒15回。画面は届いた状態の間を補間して描く
- 担当以外の操作はサーバーが `not_your_role` で拒否する
- 危険地帯の地図はナビの view にだけ、3秒おきに入れる（変わらないので毎回は送らない）。隕石は操縦と防衛の view にだけ入る。3D の景色も届いたものだけを描くので、操縦の画面には岩場が出ない
- 航路の定義は `public/routes.js`（サーバーと画面の両方が読む）。ホストの選択は `setup` で全員に配り、開始時の `route` はゲーム側でも検証する
- `startServer({ gameOpts })` でコースの長さなどをサーバー側から変えられる。画面から届いた設定は使わない
- index.html を返すとき、og:image を届いた Host から絶対URLに書き換える

## 3D の見た目（`public/view3d.js`）

- ワールドの x → 3D の x、y（前）→ 3D の -z。40単位 = 1m
- カメラ: 船の後ろ7m・上3.7m（横持ちは少し低め）。向きは船の向きにゆっくり追従。縦長の画面でも左右が見えるように横の視野角で決め、速いほど少し広げる。被弾で揺れる
- 船: クリーム色の機体にオレンジの翼、ガラスの窓の中にクルー（人数で1列か2列、少ないほど大きく）。曲がる向きに傾き、速さで噴射が伸びる。船体が減ると煙、エンジン故障で噴射が灰色
- 背景: 航路ごとの空（星雲の色）と遠くの天体（月・輪のある惑星・嵐の惑星・ブラックホール・渦巻き銀河）。流れるちりと足もとの格子で速さと奥行きを出す。航路の端は赤いブイ、中継ラインは光る帯（通ると緑）
- トゥーン（3段の陰影）。影の計算はしない（宇宙で影を落とす床が無いため。重さ対策も兼ねる）
- 重さ対策: 画素比の上限（画質 高2 / 中1.5 / 低1）、岩場の岩と隕石は InstancedMesh、粒は1つの InstancedMesh。fps が 40 を切ると画質を1段下げ、低ではちりと格子を消す（スマホは中から始める）
- 名前の札・吹き出し・画面外の矢印（目的地・目印・隕石）は HTML を重ねる
- 再戦のたびに WebGL を作り直し、前のものは返す

## デプロイ

このフォルダ1つが1つの Web サービス。WebSocket が使えるホスティングが必要（静的ホスティング不可）。

- Render: `render.yaml` をそのまま使う（ヘルスチェック `/healthz`）
- Fly.io / Cloud Run など: `Dockerfile` をそのまま使う（PORT=8080）

いまは手元の Mac から cloudflared のクイックトンネルで公開している（`../publish.sh`。URL は起動のたびに変わり、Mac が起きている間だけつながる）。

Three.js は `public/vendor/`（r185、MIT）に置いてある。CDN には頼らない。画面の文字は Google Fonts（RocknRoll One / Zen Maru Gothic / Orbitron）を読み、読めないときは端末の日本語フォントで出る。
